The /tmp regression: the same assertion, OLD image vs NEW image.

fx-init 675e801 fixed a real bug — post-pivot the tmpfs root had no /tmp, so
every `fx-*` stage (they all mkdtemp a hardcoded /tmp/<stage>-XXXXXX template)
failed in the console shell. The bug had NO fireable regression test in its own
repo: fx-init's console lane (tests/qemu_console.sh) drives `seq | head`, which
needs no /tmp, and pins exact prompt counts. The demo's assertion is where the
regression test now lives.

INSTRUMENT (identical for both halves — this is the asymmetry, not two
different checks): harness/assert.mjs as committed at 34684ca, driving the real
page in headless chromium, typing `ls /bin` and `ls /tmp` into the guest over
xterm.js -> serial0_send -> the emulated 8250 -> fxsh:

  OLD image = the PREVIOUS commit's web/ (71af537, initrd.xz sha256 83579980…,
              CMDLINE rdinit=/fx/store/dda2c337…-fx-init/fx-init)
  NEW image = this commit's web/    (34684ca, initrd.xz sha256 15f82729…,
              CMDLINE rdinit=/fx/store/85adaec9…-fx-init/fx-init)

Both runs boot to `fx-init: boot-ok` and agree on every other assertion. Two
things move, and only one of them is the point:

  * the two /tmp assertions — FALSE on the OLD image, TRUE on the NEW one. The
    guest says `error: Mkdtemp` for both commands, which is the bug verbatim.
  * `dhake-/bin/init-symlink-reads-through` — also false on the OLD image,
    because the assertion now quotes the NEW fx-init's in-guest size (826524 vs
    the old 825300). That is the binary having changed, not a regression.
